# TemenCAD

A code-driven 3D modelling playground for 3D printing. Write JavaScript on the left, see the model on the right. Scripts are strict-mode ES modules in a JavaScript subset (no classes, `var`, `for...in`, `instanceof`, generators, `eval`, `Proxy`, `Symbol` or typed arrays) so the same script runs in the browser, on the command line and on a phone; `npx temencad api language` lists it.

## Why "Temen"?

*Temen* (Sumerian **temen**, Akkadian *temennu*, written 𒋼) is the ancient Mesopotamian word for the foundation of a building: the levelled platform and the pegs that fixed its outline on the ground before the first brick was laid. In Babylonian and earlier Sumerian practice, founding a temple began with the king or priest driving the *temen* pegs and burying foundation deposits (inscribed cones, tablets and figurines) at the corners. The *temen* was the geometric plan made physical: a set of fixed points from which every wall was measured out. The word later passed into Greek as *temenos*, a sacred precinct marked out from the land around it.

That is a good description of what this app does. You lay down a few measured points and rules in code, and the model is built up from them, so the name fits.

```sh
npm install
npm run dev
```

Then open the URL Vite prints (usually http://localhost:5173).

- **Left pane**: Three.js WebGL viewport. Left-drag rotates, right-drag pans, wheel zooms.
- **Right pane**: tabs for the Assistant (shown first) and each project file in a CodeMirror editor. Scripts auto-run on change (or press Ctrl/Cmd+Enter; a ▶ Run button appears when Auto-run is off). Autocomplete suggests the built-in functions as you type and shape/sketch methods after a dot, with a signature and one-line description; Tab accepts a suggestion and then steps through its argument placeholders.
- **Projects**: a model is a `.temen` file (a zip) holding `main.js` plus any other scripts, fonts (`.ttf`/`.otf`), meshes (`.stl`), images (`.png`/`.jpg`) and SVG drawings (`.svg`, editable as text). Tabs above the editor switch between files; the **+** button adds a new script, adds files from disk, or renames and removes the current file. Scripts import each other like normal ES modules (`import { lid } from './lid.js'`, `export const lid = …`); `import logo from './Logo.ttf'` gives a font name for `text()`, `import part from './part.stl'` gives a Shape, `import logo from './logo.svg'` gives the drawing's filled shapes as a Sketch in millimetres (`extrude(logo, 2)`; `svg(markup, { width: 50 })` and `svgPath(d)` for inline drawings), and `import photo from './photo.png'` gives an image for `heightmap()` (a relief) or `lithophane()` (a back-lit picture plate). Errors and warnings point at the file and line they came from.
- **Catalogue**: **+ → Add from catalogue…** browses shared, parametric shapes (hinges, clips, knobs, boxes…) published at [belteshazzar.github.io/TemenCAD-catalog](https://belteshazzar.github.io/TemenCAD-catalog/). Adding one copies its files into `catalog/<name>/` in your project and imports it in `main.js`, so projects stay self-contained and pinned. **Menu → Share…** packages the current project (with a preview render) for the catalogue; every submission is reviewed as a pull request on the [catalogue repository](https://github.com/belteshazzar/TemenCAD-catalog). Catalogue scripts cannot use the network: `fetch` and friends are shadowed inside the geometry worker.
- **Menu** (☰ button in the top-right of the viewport): File section with New, Open… (⌘/Ctrl+O), Save (⌘/Ctrl+S), Save As… (⇧⌘/Ctrl+Shift+S) read and write `.temen` projects; opening a plain `.js` starts a new project from it. In Chromium browsers Save overwrites the opened file in place; elsewhere it downloads a copy. **Render views…** downloads a PNG sheet of labelled views (isometric, top, front, right, and more), optionally cut open at a section plane, the same picture the command line's `--png --views` makes, with any `dimension()` and `mark()` annotations the script adds drawn over it; **Export STL…** downloads the visible parts as one binary STL; **Export 3MF…** downloads them as a 3MF with each part as a named, colored object (what Prusa, Bambu, Orca and Cura prefer). Both are written Z-up in millimetres.
- **Named parts**: `shape.name('lid')`, `show(shape, { name, ghost, hidden })`, or `return { body, lid }`. The Parts flyout in the menu toggles visibility and ghosting per part, solos on double-click, and exports a single part as STL. Ghosts and hidden parts are never exported.
- **Assistant** (first tab of the right pane): a chat panel where you describe changes in plain English. The assistant edits the script, builds it, reads the same errors and warnings you see (with line numbers), and can take a screenshot to check the result. It can also do everything the menus do, so you can stay in the chat: start, open and save projects, export STL or 3MF (all parts or named ones), hand you the rendered views as a PNG, set the build plate, show, hide, ghost or solo parts, point the 3D view, toggle auto-run and wireframe, search and add catalogue shapes, prefill the Share form, and ask you to add files. Browsers only open a file picker from a click, so for opening, saving to a new file and adding files it puts a button in the chat for you to press; downloads leave a link in the chat so you can save them again. The views and screenshots it looks at appear in the conversation as thumbnails (click one to see it full size and save it). Under each reply, **⤓ STL** and **⤓ 3MF** download the model as it stands after the latest reply, and **Undo** puts the project back as it was before that reply (then **Redo** puts the reply's changes back); the assistant is told when you undo or redo. It runs entirely in your browser against the Anthropic API with **your own API key** (menu → Assistant settings…); the key is kept in local storage and sent only to api.anthropic.com, and usage is billed to your account. Default model is Claude Opus 5.5; Sonnet 5.5 is available as a faster, cheaper option. Requests opt into Anthropic's server-side fallback so a declined request is retried on a fallback model automatically.
- **View → Plate** flyout: overlays a printer build plate (Bambu, Prusa, Creality, Elegoo, Voron presets or a custom size) with a 10 mm grid and the printable volume. After each build the visible parts are checked against it; the outline turns red and the console says by how much they don't fit.
- **API reference** (last menu item) opens the full reference (`api.html`) in a new tab. Highlights: 3D primitives incl. `roundedBox`, 2D sketches (`circle`, `rect`, `roundedRect`, `slot`, …) with 2D booleans, `extrude` (twist/scale), `revolve`, `roof` (hip-roof solid from an outline) and `projection` (footprint or cut slice back to 2D), CSG `union`/`difference`/`intersect`, `hull`, `linearArray`/`polarArray`/`grid`, alignment helpers (`onPlate`, `align`, `resize`), metric screw cutters (`screwHole` with a sacrificial `bridge` layer, `nutPocket`, `heatInsert`), printable `hole`s with `teardrop` or bridged tops for horizontal holes, `split` to cut oversized parts with dowels and lay the pieces out for printing, screw `thread`s (ISO metric, trapezoidal lead screws, multi-start, left-hand, rods and threaded holes), involute `gear`s (spur and helical, `gearPair` meshed and placed for you, `rack`, internal `ringGear`, and `planetary` sets assembled and phased), `polyhedron`, `loft`, `sweep` along a `path` / `arc` / `helix` / `bezier` (mitred corners, twist-free frames, varying profiles), `minkowski` / `round` / `erode`, `shell`, edge `fillet` / `chamfer` on solids (by edge selection: top, bottom, vertical, concave, …) as well as on 2D sketches, `heightmap` / `lithophane` from images or functions, `echo` / `assert` for OpenSCAD-style debugging, and `text` / `text3d` with five bundled fonts: Inter, Inter Bold, Nunito Bold, Source Serif 4 and JetBrains Mono (all SIL OFL, Latin subsets; licenses in `src/assets/`).
- Units are millimetres, Y is up, the build plate is y = 0. 2D sketches also support `offset()` and `hull()`.
- Your project is saved to `localStorage` between reloads.

## Runtime

Models build on the TemenCAD core: the script runs on the lamassu JavaScript engine and the geometry
is Manifold, compiled together into one WebAssembly module (`core/`). The same library builds natively,
for Windows, and as a Swift package for macOS and iOS (`core/README.md`). The browser build and the
command line need the module built first: `npm run core:wasm` (Emscripten SDK on the PATH).

## Command line

The same engine runs headless in Node, so scripts can be built in CI or batch-exported without a browser:

```sh
npx temencad model.js                      # writes model.stl next to the script; imports resolve from its folder
npx temencad project.temen                 # a saved project archive
npx temencad model.js -o out/model.3mf     # 3MF with named, coloured parts
npx temencad model.js --parts              # plus one STL per part in model-parts/
npx temencad model.js --plate prusa-mk4    # check the build volume (exit code 2 if it doesn't fit)
npx temencad add parametric-hinge        # copy a catalogue package into ./main.js's project (--into project.temen)
npx temencad --list-plates
```

`log()` and `echo()` go to stdout, warnings and errors to stderr with line numbers, and a failed build exits with code 1. Ghost and hidden parts are not exported, as in the app.

Stack: Vite, Three.js (viewer), CodeMirror 6, and the TemenCAD core (`core/`): the [lamassu](https://github.com/mdy-docs/lamassu-js) JavaScript engine, the [Manifold](https://github.com/elalish/manifold) geometry kernel and the modelling API, compiled together into one WebAssembly module (fonts through stb_truetype, images through stb_image).

Architecture: the project and all geometry work run in a module Web Worker (`src/worker.js` → `src/core-runner.js` → `core/wasm`), so the editor and camera stay responsive during long builds. Inside the core, project files load as ES modules on the lamassu engine: `main.js` is the entry and runs as written, its top-level `return` handing back the parts, other scripts keep their `export`s, fonts, meshes and images become modules whose default export is the font name, the Shape or the image; errors and `echo()` lines carry the script file and line from the engine's stack traces. The worker posts back indexed vertex buffers as transferables, and the viewer (`src/viewer.js`) builds flat-shaded Three.js meshes from them. Cancel terminates and respawns the worker. Geometry objects made during a run are released in bulk when it ends; the engine context, and with it the compiled API, persists between runs.

More is there for people and agents working outside the app: `npx temencad api` prints the complete API reference as plain text, `npx temencad api sweep` just the matching section (`api --list` for the headings); `npx temencad eval "screw('M4')"` evaluates an expression with the whole API and prints the value; `npx temencad test [folders or files] [--check] [--strict] [--json]` builds every `main.js`, `.temen` and script it finds and reports which fail, for CI and model libraries (also published at [api.txt](https://belteshazzar.github.io/TemenCAD/api.txt)), and `--png out.png` renders a picture of the build so the result can be checked without a browser: `--views iso,top,front,right` (or `all`) tiles several views into one sheet with part labels, sizes, a scale bar and axes, ghosts drawn translucent; `--section y=5` cuts the model open at a plane with the cut faces in red. In the script, `clearance(a, b)`, `interference(a, b)`, `intersects(a, b)` and `overlap(a, b)` answer how parts relate, so an `assert()` can check a fit during the build; `printability(part)` (with `overhangs`, `unsupported` and `minWallThickness`) says whether it prints without supports. `s.emboss('text', s.face('front'))` and `s.engrave(...)` put lettering or a logo sketch on any face, oriented to read from outside. A `printer({ nozzle, layer, holeCompensation })` profile makes `wall()`, `layers()`, `fit()` and `peg()` derive dimensions from the printer and lets `hole()` compensate itself. Anchors (`s.anchor('tip', [x, y, z])`) are named points that travel with a shape through every transform and boolean, and `sketch().moveTo().lineTo().arcTo().fillet().close()` draws a profile like a pen. Placement by named features keeps the arithmetic out of scripts: `s.face('top')`, `cutter.at(face, [u, v])`, `part.placeOn(base, 'top')`, `lid.alignTo(body, { y: 'above' })`, `distance(faceA, faceB)` and `rectPattern` / `gridPattern` for hole patterns. On the command line, `--check` runs that on every part (exit code 3 on problems) and `--report out.json` writes parts, bounds, volumes, centre of mass, warnings, echo lines, the plate check and the check results as JSON. `AGENTS.md` / `CLAUDE.md` and the `temencad` skill in `.claude/skills/` describe the conventions and the build-check loop for coding agents.
